# M16 plan: HTML preview, collection report, reproducible PDF

Status: **superseded by `docs/adr/0018-collection-report-and-preview.md`** (2026-10-06), which folds
in the answers to D1-D14 and the spike S1 results. Kept as the proposal history; where the two differ,
ADR 0018 wins.

Inputs: `docs/plans/phase-2.md` (M16, decisions 5 and 6), `docs/HANDOFF.md` ("Next: M16"), ADR 0005,
0014 §4, 0015 (§6, §11, §14-§19), 0017.

## 0. What the code already gives us (verified 2026-10-05)
The sealed job chain already records almost every fact the report needs, so the report can be derived
from **verified custody** first and database rows second:
- `job_started`: actor, connector + version, connection id, every scope (type, id, range, thread
  policy).
- `unit_reconciled`: unit key, expected, collected, recon status, file gaps, no-longer-observed count,
  and for exports `basis: archive` + day anomalies. `unit_failed`: unit key, error type, error text.
- `job_paused` (reason, connection) / `job_resumed` (**actor** = who re-authorized, connection).
- `job_finished` / `job_cancelled`: final status, unit summary by status, `paused_ms`, stop reason.
- `items_collected` batches: Merkle roots over the linked items, which include the item-level events
  (`file_unavailable` with reason, `access_lost`, `no_longer_observed`, ...). The job custody package
  (`items.jsonl`) carries them, so an expert can recompute the report offline.
- `report_generated` is already a lifecycle event (`edisc_custody.chain.LIFECYCLE_EVENTS`).
- Not in the chain: **blind spots, plan tier, granted scopes** (only in the tenant audit stream's
  `audit.connection_created` / reauthorize payloads and `slack_exports.findings`); evidence lock
  settings; retention gaps; renders (their own streams).
- Constraint: **a sealed job chain is never appended to.** So `report_generated` cannot go in the job's
  stream; a report gets its own stream, exactly like a render (ADR 0015 §7, §14).

## 1. The outputs, what they contain, who can access them

### 1.1 Collection report (one per report id; files)
| File | Format | Bounded? | Content |
|---|---|---|---|
| `report.json` | RFC 8785 canonical JSON | yes | the summary: everything in the list below, with totals, plus the SHA-256, size and row count of every `.jsonl` |
| `units.jsonl` | one canonical JSON object per line, LF, ordered by (conversation id, day, unit key) | no (one line per unit) | per unit: key, kind, conversation, day, scopes covering it, status, recon status (verbatim enum), expected, collected, file gaps, no-longer-observed, access-lost reason, failure type + text, archive basis + day anomalies |
| `observations.jsonl` | same, ordered by (`unit_key`, `item_id`) | no | every item-level event of the job: `file_unavailable` (file id, reason), `file_became_available`, `access_lost` / `access_restored`, `no_longer_observed` / `observed_again` |
| `renders.jsonl` | same, ordered by render id | no | every render of the job sealed at the report's snapshot: id, identity (triple, options hash), status, head, seal, file count, natives count and bytes, and each external native (`{file_id}_EXTERNAL.txt`, SHA-256, size) — ADR 0015 §11 requires the report to list them |
| `report.html` | static HTML, one inline stylesheet | yes (D5) | human-readable rendering of `report.json` |
| `report.pdf` | PDF rendered from the stored `report.html` bytes | yes (D5) | the same, paginated |

`report.json` sections (each one states its **source**, see §4):
1. **Job:** ids (tenant, client, matter, workspace, job, rerun-of), requester, created/finished/sealed,
   final status VERBATIM, `clean` (true only for `completed`), `clean_basis`, the archive caveat.
2. **Scopes:** type, external id, range, thread-parent policy; units per scope.
3. **Access:** source, connection, access tier, plan tier, granted scopes, **blind spots** (D7); for
   exports: the export id, SHA-256, size, validation findings, tier detection, blind spots.
4. **Counts:** units by status and by recon status (every enum value, zeros included), expected,
   collected, file gaps, per conversation (the per-conversation table is in `units.jsonl` aggregates
   when large, D5).
5. **Exceptions:** gap, unverifiable, surplus, access-lost and failed units with reasons; file
   unavailability by reason; no-longer-observed and access-lost observations; orphaned evidence
   (ARCHITECTURE.md lists it in the report).
6. **Pauses:** each pause: reason, connection, paused at, resumed at, duration, **who re-authorized**
   (`job_resumed.actor`), and pauses never resumed.
7. **Versions:** connector, normalizer versions used (from `item_derivations`), report renderer, PDF
   toolchain, Unicode; the worker image digest (ADR 0017 §1).
8. **Actors:** every custody event's actor grouped by action (job started, cancelled, resumed, rerun,
   ...), plus the audit events for the job (render requests, report requests).
9. **Custody verification:** the result of `verify_chain` on the job stream with the seal required
   (events, batches, items, files, anchors checked, head, seal key + VersionId listed from S3, errors).
10. **Evidence store:** bucket Object Lock mode and default retention, versioning (observed from S3 at
    the snapshot, with the observation time), evidence retain-until range for the job, **retention
    gaps** (ADR 0002) touching the job's objects.
11. **Renders and natives** (summary; list in `renders.jsonl`).
12. **Divergences:** every mismatch found between the chain and the database (§4.3). Empty list = none
    found; the section is always present.
13. **Integrity of the report:** the snapshot digest, the `.jsonl` hashes, the report identity.

The report never contains message text or file bytes. It does contain conversation names, custodian
names and error texts (`unit_failed.error`, up to 2,000 characters, which can quote source data).

### 1.2 HTML preview (on demand, not stored)
- One page per (job, conversation, day, page), the day in UTC or a requested time zone (same slicing
  as RSMF, `local_day_bounds`), at most `PREVIEW_PAGE_EVENTS` events per page (D10, proposed 1,000).
- Built from the same intermediate as RSMF: the render loader's `SliceInput`, so threads, edits,
  deletions (tombstones), reactions, deleted messages' reactions only as history (ADR 0015 §18.1),
  joins/leaves, bots, attachments, placeholders for unavailable files, marked thread context.
- Attachments are **links only** to `/v1/evidence/{id}/content?purpose=preview` (the pinned file
  evidence id). No inline images (D10).
- A header per page: job status and clean flag, the unit's status for this day (expected / collected /
  recon status / file gaps / access lost), the archive caveat if archive-relative, and the page's
  identity (source hash of the slice, preview renderer version).

| Action | Permission (proposed) | Roles |

## 2. Byte identity

### 2.1 JSON and JSONL
Canonical JSON (`edisc_core.canonical`), LF line ends, every list in a defined order (the order is part
of the format spec), integers only (durations in ms, sizes in bytes), times as UTC ISO 8601 with `Z`
(`edisc_core.time.format_utc`). No report id, no generation time, no host name in any output: the
report id sets storage keys, never bytes (as for renders). Times that appear are RECORDED times (seal,
pause, snapshot observation), never the clock.

### 2.2 HTML
- A pure builder `edisc_renderers.report.html` (and `edisc_renderers.preview`): no DB/S3/clock imports
  (the existing purity test extended to both). **No template engine** dependency: a tiny element
  builder whose only text path is `escape()`, so a template engine's version cannot move bytes and
  there is no unescaped path to forget.
- Fixed bytes: `<!doctype html>`, UTF-8, one constant inline `<style>` (its SHA-256 goes in the CSP),
  attributes in a fixed order, LF, our own integer formatting (no locale), no trailing whitespace.
- User strings (names, error texts, message text in preview) are NOT normalised (forensic: shown as
  collected) but are made safe and visible:
  - HTML-escaped (`& < > " '`), wrapped in `<bdi>` so RTL text cannot reorder the surrounding layout;
  - bidi controls (U+202A-U+202E, U+2066-U+2069), zero-width and other `Cf` characters, C0/C1 controls
    and lone surrogates (cannot occur after JSON, but checked) are shown as a visible marker
    `⟦U+202E⟧` next to the original. This depends on `unicodedata`, so the Unicode version is in the
    identity (already pinned by `.python-version`).
  - URLs inside message text are plain text, never `<a>` (no navigation away, no referrer leaks).
- Report HTML: no fonts embedded (the HTML is not a layout promise; the PDF is).
- Identity: `REPORT_RENDERER_VERSION` / `PREVIEW_RENDERER_VERSION` + Unicode (+ tzdata for the
  preview's time-zone days). The report shows times in **UTC only** (D11), so it has no tzdata input.

### 2.3 PDF (D1-D4)
**Recommended engine: WeasyPrint** (HTML/CSS → PDF, Python), rendering the stored `report.html` plus a
constant print stylesheet (`@page` size A4/Letter (D-minor, A4 proposed), running header/footer).
It is the only mainstream engine that renders our HTML directly without a browser. Its bytes depend on
native libraries (Pango, HarfBuzz, FreeType, fontconfig, and zlib if streams are compressed), so:
1. **Pinned image.** PDFs are produced only by a report worker running a pinned image (ADR 0017
   mechanism, D2). The Python side is pinned by `uv.lock` (weasyprint, pydyf, fonttools, tinycss2,
   cssselect2, Pyphen — Pyphen OFF: no hyphenation); the native side by the image digest.
2. **PDF toolchain id** computed at worker start (`python -m edisc_worker.versions`): SHA-256 over the
   canonical JSON of {weasyprint, pydyf, fonttools versions; Pango, HarfBuzz, FreeType, fontconfig
   runtime versions read from the libraries; the SHA-256 of every vendored font file; the SHA-256 of
   our `fonts.conf`; the print stylesheet hash; platform `linux/amd64`}. Short form in the queue name
   and golden key. A worker whose id differs from the report's identity refuses (safety net, as RSMF).
3. **Fonts vendored, system fonts impossible:** `FONTCONFIG_FILE` points at our `fonts.conf` listing
   only `packages/renderers/.../report/fonts/` (OFL Noto families with `SOURCE.md` + SHA-256, D13). A
   test poisons the system font directories (like the tzdata test) and the bytes do not change.
4. **No missing glyphs:** before PDF rendering, a pure pass replaces any character not covered by the
   vendored fonts' cmaps (coverage table computed at build from the fonts, part of the toolchain id)
   with the visible `⟦U+XXXX⟧` marker. Never tofu, never a silent substitute. `report.json` keeps the
   exact string.
5. **Fixed metadata:** `/ID` = both halves derived from `sha256(report.html)`; `/Producer` constant;
   `/CreationDate` and `/ModDate` = the job's `sealed_at` (recorded; or omitted, D4); title from the
   job id; no XMP timestamps beyond those; `pdf_identifier` set explicitly.
6. **Uncompressed streams (recommended, D4):** deflate bytes depend on the zlib build (the reason RSMF
   zips are STORED, ADR 0015 §6). The report PDF is bounded (D5), so the size cost is small, and a
   security rebuild of the base image cannot move the bytes.
7. **Platform:** the promise is for `linux/amd64` (HarfBuzz/FreeType positioning uses floating point
   whose results may differ by architecture). The spike checks arm64; if identical, both are admitted
   with one golden; otherwise arm64 workers do not serve the report queue (D3).
8. **Spike first (S1, before ADR 0018 is final):** in the image, render a corpus report 2x per process,
   in 2 processes, with poisoned fonts/locale/TZ/hash seed, on amd64 and arm64; inspect the bytes for
   anything time- or random-derived (font subset tag prefixes, object ordering); run veraPDF if PDF/A
   is chosen. The ADR records what was found. If WeasyPrint cannot be made byte-stable, the fallback is
   Typst (single static binary, deterministic by design, `--ignore-system-fonts`,
   `--creation-timestamp`), at the cost of a second template fed from `report.json` instead of the HTML
   (contradicts phase-2 decision 6's "same HTML template", so it needs your sign-off). Headless
   Chromium is rejected (timestamps, random ids, Skia rasterisation, huge surface).

### 2.4 ADR 0017 (D2)
Recommended: **join it, generalised from "renderer triple" to "runtime identity per output kind"**:
- one worker image may serve several identities; `deploy/render-images.json` records per image digest
  the identities it serves (`rsmf: r1.3.1-u15.0.0-tz2026e`, `report: r1.0.0-p<toolchain>-u15.0.0`);
- the report queue is `reports.r<renderer>.p<toolchain12>.u<unicode>`; workers poll the queues of
  their own runtime; routing check + `unroutable` episodes as for renders (generalise
  `render_episodes` to `production_episodes` keyed by (kind, id), or add `report_episodes`, D-minor);
- admission: the report oracle cases pass and the report golden generation matches inside the image;
- the image digest goes in `report_started`; retention of images counts report productions too;
- reproductions (ADR 0017 §4) apply to reports later (`POST /v1/reports/{id}/reproductions`, backlog).
The preview is NOT a production: it runs in the API process on the API's runtime, is deterministic for
that runtime (tested), records its identity and output hash in the audit, and carries no promise to be
reproduced on a later runtime (D10).

## 3. Nothing looks clean that isn't
Rules, each with a test (§9):
1. **One function decides "clean"** for every output: `status == completed` AND custody verification
   ok AND no divergences AND no retention gap overlapping the job's evidence. It reuses
   `JobStatus.is_clean`; the report adds the last three conditions. `clean_basis` as in the API
   (`source` / `archive` / none).
2. **Banner on top of the HTML and on EVERY PDF page** (running header via `@page` margin boxes), in
   words, never colour alone (prints in black and white):
   - `completed`, clean → "Complete: every unit reconciled against the source".
   - `completed_against_archive` → "COMPLETE RELATIVE TO THE PROVIDED EXPORT ONLY" + `ARCHIVE_CAVEAT`
     verbatim (byte-equal to `edisc_core.schemas.ARCHIVE_CAVEAT`, tested), also next to every
     archive-relative count.
   - `completed_unverified` → "NOT VERIFIED: N units could not be checked against a source count".
   - `completed_with_gaps` / `completed_with_failed_units` / `failed` / `cancelled` → "NOT COMPLETE:"
     + the counts that make it so.
   - custody verification failed or divergences → "CUSTODY VERIFICATION FAILED" / "RECORDS DISAGREE"
     above everything else, whatever the job status.
   The footer of every page repeats job id, report snapshot digest (short) and "page X of Y", so an
   excerpted page still names its report and status.
3. **Every enum value is listed** in count tables, zeros included, in a fixed order: a missing "gap"
   row can never be read as "no gaps".
4. **"None" vs "unknown":** a fact with no recorded source is printed "UNKNOWN (not recorded)", never
   "none" or an empty list (e.g. blind spots of a job whose connection predates the record, D7).
5. **Verbatim statuses:** `units.jsonl`, the HTML and the PDF use the enum values verbatim next to any
   wording. `matched_against_archive` is never shown as "matched" and never gets the clean mark.
6. **Exceptions before totals:** the exception sections come before the counts, and a capped list says
   exactly how many rows are not shown and where they are ("4,812 more in units.jsonl, SHA-256 …").
7. **Preview:** the per-page header shows the day's unit status; a day whose unit is `gap`,
   `unverifiable`, `access_lost` or `failed` gets a banner ("Expected 120, collected 117"); unavailable
   files show the reason; deletions are tombstones with their earlier text under "edits"; context
   messages are marked "context, outside the collection scope"; a day in scope with zero messages says
   "0 messages (unit status: matched, expected 0)", a day outside every scope is a 404
   `not_in_scope`, never an empty page.

## 4. Sources, verification, custody and audit

### 4.1 Report lifecycle and custody stream (stream id = report id)
Records: `reports` (status `requested → snapshotted → generating → generated → completed`, or
`refused` / `failed`; guard trigger on transitions and identity, like `renders`) and `report_files`
(insert-only). Identity: (job, snapshot digest, report renderer, PDF toolchain, Unicode); one live
report per identity (partial unique index), so asking again with nothing changed returns the existing
report.

1. **Snapshot** (tx, status `requested → snapshotted`): everything mutable the report depends on is
   captured ONCE into `reports.snapshot` (write-once JSONB) and its digest: the renders of the job
   sealed now (id + seal head), retention gaps touching the job (ids), the S3 lock settings observed
   now (with observation time), the tenant audit stream head (seq, hash) bounding the audit events
   used, the blind-spot source (D7). A retry before commit re-snapshots; after commit it is fixed.
2. **`report_started`** (tx, `snapshotted → generating`), only after: the job is sealed; its chain
   verifies with the seal required; the seal key is exactly one S3 object version anchoring that head
   (listed from S3, as `render_started`). Payload: job ref (id, status, basis, final head, seal key +
   VersionId), snapshot digest, versions, image digest, requester. On a failed verification see D8
   (recommended: still generate, with the failure as the headline; `report_refused` only for
   "job not sealed").
3. Output files (§5), each recorded in `report_files` when complete.
4. **`report_generated`** (lifecycle, tx, `generating → generated`): every file (name, media type,
   SHA-256, size, VersionId, row count), the RFC 6962 root over the file records, the clean verdict,
   divergence count.
5. **Seal** (forced anchor of the report head) + `audit.report_completed` in one tx. `report_failed`
   (error class, status it failed from, progress) is sealed too; `fail_report` retried without limit;
   stuck sealing opens an episode, as renders (§15/§16).
Tenant audit: `audit.report_requested` (actor, job, created/returned), `audit.report_completed` /
`_failed` / `_refused`, `audit.report_divergence` (+ alert `report_divergence`).

**Who triggers it (D6):** a maintenance schedule `ensure-job-reports` finds sealed jobs without a
report and starts `ReportWorkflow` (actor `system`), so every sealed job gets one, including failed and
cancelled jobs; no command change in `CollectionJobWorkflow` (no new `workflow.patched`). A manual
`POST /v1/jobs/{id}/reports` makes a new snapshot (e.g. after renders were added); identical snapshot
→ the existing report (200), new snapshot → new report (201). Older reports stay, listed with their
snapshot time.

### 4.2 Where each fact comes from
| Fact | Primary source | Cross-check |
|---|---|---|
| job, scopes, connector version, requester | `job_started` (verified chain) | `collection_jobs`, `collection_scopes` |
| per-unit expected/collected/recon/gaps | `unit_reconciled`, `unit_failed` | `work_units` rows (additive digest, §6) |
| item-level observations | `items` via `job_items`, covered by `items_collected` Merkle roots | counts vs `unit_reconciled.file_gaps` / `no_longer_observed` |
| pauses, who re-authorized | `job_paused` / `job_resumed` | `job_pauses` |
| final status, unit summary | `job_finished` / `job_cancelled` | `collection_jobs.status` |
| blind spots, plan tier, scopes granted | D7 (recommended: `job_started` for new jobs; the latest `audit.connection_created`/`_reauthorized` before `job_started`, by seq + hash, for old ones) | `connections` row |
| export findings | the export's audit events (by seq + hash) | `slack_exports.findings` |
| normalizer versions | `item_derivations` of the linked items | — |
| renders, natives | each render's sealed stream + `render_files` / `render_natives` | render seal listed from S3 |
| retention gaps, lock settings | snapshot | — |
Each section of `report.json` carries its `source` (`job_chain`, `audit_stream@seq`, `database`,
`s3_observation@time`), so a reader knows which facts an offline verifier can re-derive.

### 4.3 Divergences (D8)
Any disagreement between a primary source and its cross-check (a `work_units` row that differs from
its `unit_reconciled`, a unit with two reconciliation events, a status that differs from
`job_finished`, observation counts that differ from the unit's) is listed in the report's divergence
section, makes the report not clean, records `audit.report_divergence` and raises one alert. The chain
value is what the report states as the fact. (Recommended over refusing: the report is where a problem
must be documented, and this mirrors the anchor-divergence decision of ADR 0015 §19.14.)

### 4.4 Reads anchored before the first byte
- **Report inputs:** the job chain is verified (seal required, seal listed from S3) before
  `report_started`; renders included are re-checked against their seals at snapshot; the PDF is
  rendered from `report.html` READ BACK from WORM by pinned VersionId and checked against its recorded
  SHA-256 (it never trusts the in-memory copy).
- **Report bytes served:** `GET /v1/reports/{id}/files/{name}/content` and
  `GET /v1/reports/{id}/package` (`edisc-report-package/1`: report chain, job seal, files, anchors
  listed from S3, `objects/`) follow the render rules exactly: audit committed (`audit.report_read` /
  `audit.report_package_read` with manifest SHA-256, purpose, request id) AND `audit.anchor_now`
  before the response starts; streamed re-hash, a mismatch aborts with `audit.report_read_aborted` +
  alert; exact `Content-Length`; anchor divergence recorded as §19.14. Each route gets a
  `first_byte.py` test. Only `completed` (sealed) reports are served; `/v1/evidence/{id}/content` never
  serves report rows.
- **Preview:** authorize → load the slice (every page/archive entry by pinned VersionId, checked as the
  loader does today) → reconcile the slice (every in-scope message of that day exactly once) → render
  to bytes (bounded by the page cap) → SHA-256 → commit `audit.preview_read` (job, conversation, day,
  tz, page, slice source hash, preview identity, output SHA-256 and size) → `audit.anchor_now` → first
  byte. Any failure before that records `audit.preview_refused` with the reason (integrity → alert).
  Headers: `Content-Security-Policy: default-src 'none'; style-src 'sha256-…'; img-src 'none';
  base-uri 'none'; form-action 'none'; frame-ancestors 'self'; sandbox allow-top-navigation-by-user-activation`
  (the CSP also as `<meta>` in the document), `X-Content-Type-Options: nosniff`,
  `Cache-Control: no-store`, `Referrer-Policy: no-referrer`.
  Risk for M17 (not decided here): a `sandbox`ed document has an opaque origin, so SameSite=Strict
  session cookies may not accompany an attachment link click; the M17 Playwright flow must cover it.
- Cost: one forced WORM anchor per preview page view (CLAUDE.md rule for evidence bytes). Measured
  with `scripts/measure_audit_burst.py` in step 6; D14.

### 4.5 Storage and retention
Report files are `report` registry rows (kind already in ARCHITECTURE.md), origin `report`, at
`t/{tenant}/reports/{report}/{name}`, written like productions (`EvidenceWriter.write_production`
path: hashed while streaming, multipart, Object Lock at create, our SHA-256, under the per-key content
lock). `evidence_objects.report_id` (new, like `render_id`); retention and the extension job resolve
report → job → matter; anchors of report streams carry the report id.

## 5. Scale (millions of conversation-days)
- **Generation is one streaming pass per file**, memory O(page): keyset pages by `unit_key` (and by
  item id for observations), short transactions, never a transaction across S3 I/O, linked items
  selected BY ID then filtered in Python (CLAUDE.md, stale statistics).
- **Chain cross-check without a per-unit map:** the chain pass (already streamed by `verify_chain`'s
  pager) folds every `unit_reconciled`/`unit_failed` record into an additive digest (the
  `_add_digests` construction the loader uses) and counts per status; the `units.jsonl` pass folds the
  same canonical record per row. Equal digests and counts prove the file says what the chain says, in
  O(1) memory. The keyset pages follow the file order, which needs an index on `work_units`
  (job_id, conversation_id, day, unit_key) (migration 0030). To locate a difference, both passes also fold into
  4,096 buckets by `sha256(unit_key)` (a fixed 128 KiB of state); only units of mismatching buckets
  are re-read in a second pass, compared one by one and listed as divergences.
- **Sizes:** about 300 bytes per unit line → about 1 GB of `units.jsonl` for 3M units, streamed into a
  multipart upload. `report.json`, HTML and PDF are bounded by D5 (proposed: at most 1,000 rows per
  exception category and per conversation table in HTML/PDF; exact totals always; the remainder named
  by file and hash). A PDF of millions of rows is not a usable artefact and WeasyPrint lays out the
  whole document in memory, so a full-listing PDF is out (D5).
- **Per-conversation aggregates** (`conversations.jsonl` when the job has more conversations than the
  cap), computed in the same units pass: `units.jsonl` is ordered by (conversation id, day, unit key),
  so each conversation's units are contiguous and its aggregate is emitted when the next one starts.
- **Verification cost:** `verify_chain` over millions of events is the dominant cost; it runs once per
  report (measured, `docs/runs/`).
- **Preview:** the loader today indexes a whole conversation (`RenderLoader._index`); the preview
  needs a new day-bounded entry point `RenderLoader.day_slice(conversation, window, page)` that loads
  only the day's subjects plus the thread roots it references (`missing_roots` otherwise), so preview
  cost is independent of conversation length. Page cap bounds memory.
- **Measurements:** `scripts/measure_report.py` (new): synthetic jobs of 10k, 100k, 1M units on the
  test stack (units and chain rows inserted through the pipeline's own functions, not hand SQL); peak
  RSS flat across sizes (asserted at 10k vs 100k in an integration test), throughput recorded in
  `docs/runs/`. The 50k SIGKILL acceptance job gets a report and an oracle check.

## 6. Crash points (resumability)
The status is the fence (moved in the same transaction as the event). Points, each tested at the 1st
and 2nd occurrence where it repeats:
1. inside / after the snapshot transaction;
2. after chain verification, before `report_started`; inside / after the `report_started` transaction;
3. mid-upload of each `.jsonl` (multipart open: aborted and restarted; deterministic bytes, so the
   retry yields the same SHA-256), after the object is written but before its `report_files` row
   (the retry finds the version by listing under the content lock, as `write_native`), after the row;
4. after `report.json`, after `report.html`, mid-PDF (worker killed while WeasyPrint runs), after the
   PDF object, before its row;
5. inside / after the `report_generated` transaction;
6. seal sub-steps (`seal_start`, `after_seal_anchor`, `seal_tx`, `sealed`) with REAL SIGKILLs through
   the test barrier (`EDISC_TEST_REPORT_BARRIER`, test/ci only, as the render barrier);
7. failure path (`fail_report` interrupted) and refused path.
Expected after every resume: the same bytes as an independent in-memory generation from the oracle,
every event and audit once, one object version per key, no pending row, a verified chain and a verified
package. Plus: two identical requests racing on the identity (one report, one set of events); the
`ensure-job-reports` schedule racing a manual request; the anchor sweeper racing a recovering report.
Preview has no stored state: a crash mid-response leaves an audit record without a completed transfer
(the client sees a short body against `Content-Length`).

## 7. Offline verification
`edisc-verify` learns `edisc-report-package/1`: the report chain, the job seal it references, every
file's SHA-256/size, nothing unlisted (strict). With `--job-package` (recommended, D12) it also
**recomputes** `units.jsonl`, `observations.jsonl` and the chain-derived sections of `report.json`
from the job custody package (`events.jsonl`, `items.jsonl`) with the same pure code
(`edisc_renderers.report.model`, DB-free, importable by the verifier) and compares bytes. Facts whose
source is the snapshot, the audit stream or an S3 observation are checked against their recorded
digests only, and the verifier output says so.

## 9. Test plan (expected values from oracles, never from collected data)
**Report oracle** (`tests/integration/report/oracle.py`): computes the expected `report.json`,
`units.jsonl` and `observations.jsonl` from the dummy `Dataset`, the job's scopes and the scenario's
injected conditions (which units throttle into gaps, which files are unavailable and why, which
conversations lose access, the pause and the re-authorizing actor, epochs for no-longer-observed).
Named cases, each collected through the real pipeline: clean live; gaps; unverifiable;
failed units; cancelled; failed job; paused + re-authorized by a named principal (actor and duration);
access lost and restored; no-longer-observed across a rerun; file unavailable (each reason);
export job (`completed_against_archive`, caveat verbatim, export findings, blind spots); multi-scope
with overlapping ranges; renders with external natives; a retention gap; a job whose connection
predates blind-spot recording (UNKNOWN shown). A coverage matrix (like `oracle.COVERAGE`) must be
exercised.

**Never-clean property:** for every `JobStatus` × custody result × divergence × retention-gap
combination (hypothesis over generated report models, plus the real cases): the clean label appears in
HTML and in the text of EVERY PDF page iff the clean function is true; otherwise the required banner
words appear on every page; `ARCHIVE_CAVEAT` appears byte-equal wherever the basis is archive; every
enum value has a row.

**Determinism:** two generations (different report ids, processes, `PYTHONHASHSEED`, `TZ`, `LANG`,
frozen clocks at different instants, poisoned system fonts and zoneinfo) → identical bytes for every
file; goldens per identity key under `tests/golden/report/<key>_dummy-<v>/` (`EDISC_RECORD_REPORT=1`,
never overwrites, refused in CI); PDF goldens checked only inside the pinned image (CI job runs there).

**PDF structure** (pypdf, pinned): parses; `/ID` and dates as specified; no `/JavaScript`,
`/OpenAction`, `/AA`, `/Launch`, `/URI` or `/EmbeddedFile`; every font embedded and from the vendored
set; no glyph 0 (`.notdef`) used in any content stream (fontTools over the subsets); extracted text of
the hardest names (RTL, CJK, emoji ZWJ, combining, U+202E) equals the glyph or the `⟦U+…⟧` marker;
veraPDF if PDF/A (D4).

**Sanitiser** (both renderers, hypothesis fuzzing over every user-string field, including `</style>`,
`<script>`, `"><img onerror=…>`, `javascript:`, NUL-adjacent text, bidi overrides, 40k-character
messages): the output parsed with html5lib (pinned) contains only the allowed elements and attributes,
no event handlers, no URL other than `/v1/evidence/{uuid}/content?purpose=preview`, exactly one
`<style>` whose hash is the CSP's, every control/bidi/Cf character revealed.

**Preview oracle:** for every RSMF corpus case's conversation-days, the preview's events (read back
from stable `data-` attributes) equal the RSMF oracle's events for that day: every in-scope message
once, edits, tombstones, reactions (and the deleted-message history rule), placeholders with reasons,
context marked, `parent_not_rendered` reasons, DST days (23 h / 25 h), +05:45. Pages split at the cap
(N and N+1 events). A long conversation (years) previews one day with a bounded number of queries.

**API:** permission matrix per role (403/404) for every new route; first-byte tests (report file,
report package, preview); audit payloads (output SHA-256 in `audit.preview_read` equals the bytes
served); the credential scan; headers (CSP equals the style hash, nosniff, no-store); attachment links
resolve to the pinned evidence ids and are audited with purpose `preview`; 404 `not_in_scope`; 409 on
unsealed jobs.

**Custody, crash, verifier:** §6 matrix with real SIGKILLs; chain verification; package verification
including recomputation; tamper tests (edit a `work_units` row as superuser → divergence shown,
alert raised, not clean; edit a stored report object version → read aborts with alert; drop a line of
`units.jsonl` in a package → verifier fails).

**Scale:** peak memory flat 10k vs 100k units (integration); the 50k acceptance job's report against
its oracle; `measure_report.py` 1M on the cloud VM when available.

**Mutation checks:** one catalog entry per protection: the clean function, each banner, the caveat,
zero rows, UNKNOWN vs none, escaping, `<bdi>`, invisible reveal, CSP hash, glyph-coverage pass, `/ID`
derivation, uncompressed streams, font isolation, digest cross-check, divergence recording, audit and
anchor before the first byte (three routes), the stream re-hash, PDF-from-stored-HTML, the status
fences, the verifier's recomputation and strictness.

## Decisions needed from you
- **D1. PDF engine:** WeasyPrint in a pinned image (recommended), gated by spike S1; fallback Typst
  with a second template from `report.json` (departs from "same HTML template"); Chromium rejected.
- **D2. ADR 0017:** generalise to runtime identities per output kind, with reports on their own
  version-keyed queue and admitted in the same image registry (recommended); or a separate mechanism.
- **D3. Platform:** promise PDF bytes on `linux/amd64` only (platform in the toolchain id),
  arm64 admitted only if S1 shows identical bytes (recommended).
- **D4. PDF format:** uncompressed streams (recommended); dates = job `sealed_at` vs omitted;
  PDF/A-2u (only if veraPDF passes in S1) or plain PDF 1.7; A4 or Letter.
- **D5. Bounded HTML/PDF:** exact totals always, at most 1,000 rows per exception category in
  HTML/PDF, full lists only in the JSONL files named by hash (recommended); or full listings in HTML
  with only the PDF capped.
- **D6. Trigger:** a report for every sealed job automatically (maintenance schedule) plus manual
  regeneration as new snapshots (recommended); or manual only.
- **D7. Blind spots source:** add plan tier, granted scopes and blind spots (and the export findings
  digest) to the `job_started` payload for new jobs, and for older jobs use the latest connection audit
  event before the job, referenced by seq + hash, labelled with its source; UNKNOWN if none
  (recommended).
- **D8. Integrity problems at report time** (chain fails to verify, DB disagrees with the chain): still
  generate a report that leads with the failure, plus an alert (recommended); or refuse the report.
- **D9. Access:** `report.read` for tenant_admin, client_admin, matter_manager, auditor and reviewer
  (not collector); `report.create` for tenant_admin and matter_manager; preview under `evidence.read`
  (recommended); or a separate `preview.read`.
- **D10. Preview:** sealed jobs only; rendered on demand, not stored; 1,000 events per page; output
  hash in the audit; attachments as links only, no inline images; URLs in text never clickable; no
  cross-version reproduction promise (recommended for all).
- **D11. Times in the report:** UTC only (recommended), or also the matter time zone (adds tzdata to
  the report identity).
- **D12. Verifier recomputation:** `edisc-verify --job-package` recomputes the chain-derived report
  content and compares bytes (recommended; makes the report model a pure, verifier-importable package).
- **D13. Font set:** Noto Sans, Sans Mono, Arabic, Hebrew, Devanagari, Thai, CJK SC/JP/KR subsets
  and Noto Emoji (monochrome), with uncovered characters shown as `⟦U+XXXX⟧` (recommended); or a
  smaller Latin-only set relying on the marker more often.
- **D14. Preview audit cost:** keep one forced anchor per preview page view (CLAUDE.md rule;
  recommended, measured in step 7), or batch preview reads under a coalesced anchor (needs a rule
  change).
