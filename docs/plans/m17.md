# M17 plan: browser sessions, source install flows, the UI's read endpoints, live updates, a stable API

Status: **reviewed 2026-10-12, every decision taken 2026-10-14** (§12; ADR 0016 Amendments 1
and 2). Steps 0 and 2 are built; nothing else is. Inputs: `docs/plans/phase-2.md` (M17, "M17
backend", decision 7), ADR 0016 (accepted 2026-10-03), ADR 0013 (tenant from the host, OIDC, roles),
ADR 0009 (token envelope encryption), ADR 0010 (rate limits), ADR 0012 (auth pauses), ADR 0018 §28
(unit facts in the chain). Where this plan changes ADR 0016, the change is listed in §11 and goes into
an ADR 0016 amendment **before code**.

## 0. What exists today, and two problems found while planning (verified 2026-10-12)

What exists:
- Bearer auth only (`edisc_api.auth.Authenticator`): tenant from the Host subdomain, the token's IdP
  from `tenant_idps`, an active principal; every failure is the same 401; failures throttled per
  (host, client address) in Redis.
- `authorize(session, caller, P.X, Scope)` with 404/403 semantics; `visible_ids` for lists;
  `ROLE_PERMISSIONS` in `authz.py`; `openapi_extra=perm(...)` on every route (62 routes).
- Keyset pagination on the row id (`edisc_api.pagination`), limit 1..200; unit lists keyset on the
  unit key. Cursors are unsigned base64 positions; every query re-applies tenant RLS and visibility.
- `require_recent_sign_in(caller)` is a no-op hook (ADR 0016 §4), already called by render creation.
- Connections: `POST /v1/clients/{c}/connections` and `POST /v1/connections/{id}/reauth` take
  `credentials.access_token` in the JSON body (`SecretStr`, redactor-registered, envelope-encrypted
  through `connection_tokens.store_tokens`). This is the only credential path today.
- Revoked credentials: `AuthenticationError` pauses EVERY running job on the connection
  (`paused_awaiting_reauth`, `job_paused` custody event, `job_pauses` row, one `reauth_required`
  alert, connection status `reauth_required`); re-authorization resumes them (`job_resumed` names
  the acting user). There is no deadline: a paused job waits until re-authorized or cancelled.
  Per-conversation loss of access (bot removed from a channel, 403 on a team) is already a unit
  closed `access_lost` with a reason, recorded in the chain (§28).

**Problem 1 (a live bug, fix first): validation errors echo request values, credentials included.**
FastAPI's default 422 body includes each error's `input`. Reproduced against the same model shape the
connections route uses:
`{"access_token": "...", "token": "xoxb-SECRET-2"}` answers
`{"detail":[{"type":"extra_forbidden","loc":["body","token"],...,"input":"xoxb-SECRET-2"}]}`, and a
token sent as a list is echoed whole. A credential in the wrong field, or of the wrong type, is
reflected into a response body (client logs, proxies, error trackers, the browser). The existing
credential scan never sends a malformed body, so it cannot see this. **Step 0** replaces the handler
for `RequestValidationError` globally: `type`, `loc`, `msg` only; never `input`, never `ctx`; tests
send every credential-bearing model a misplaced field, a wrong type and an over-long value and scan
the answer (and the log capture) for the canary.

**Problem 2 (design): the generic credential endpoint.** Once the install flows exist,
`POST /clients/{c}/connections` with `credentials` would be a second way to type a token into the
browser, contradicting ADR 0016 ("the one exception"). Proposed (decision D10): it stays for the
`dummy` source in local/test/ci only (where `source_permitted` already guards the dummy), and is
refused (422 `use_install_flow`) for `slack`, `teams` and anything else; `reauth` with credentials
likewise. Slack internal apps use §6, Slack's distributed app and Teams use §2.

## 1. Browser sessions (OIDC, ADR 0016 §1-§4)

### 1.1 Tables (migration 0036; FORCE RLS, grants, drift test)
- `login_attempts`: `id`, `tenant_id`, `handle_hash` (SHA-256 of the cookie handle), `state_hash`,
  `nonce`, `pkce_verifier` (encrypted with the tenant's `SecretBox`, context
  `tenant + login_attempt + "pkce"`), `return_to`, `reauth` (bool), `reauth_session_id`,
  `started_at`, `expires_at` (10 min), `consumed_at`, `outcome`. Insert-only plus one `consumed_at`
  update (trigger forbids anything else).
- `sessions`: `id`, `tenant_id`, `principal_id`, `id_hash` (SHA-256 of the 256-bit id; the id
  itself is never stored), `created_at`, `authenticated_at` (the IdP's `auth_time`, else the callback
  time), `last_seen_at`, `idle_expires_at`, `absolute_expires_at`, `revoked_at`, `revoked_by`,
  `revoke_reason` (fixed list: `logout`, `self`, `admin`, `principal_deactivated`, `rotated`,
  `idle`, `absolute`), `user_agent` (truncated, sanitised), `ip_first`. Unique index on `id_hash`.
  No deletes (CLAUDE.md): expired rows stay; a retention job may later archive them (BACKLOG).
- Server keys: the CSRF HMAC key and the cookie handle pepper come from settings as `SecretStr`
  (keyring with a `kid`, so a rotation accepts the previous key for one absolute lifetime).

### 1.2 Flow
1. `GET /v1/auth/login?return_to=&reauth=1`: tenant from the host (unknown host: the same generic
   401 page as today, no enumeration). `return_to` validated exactly as ADR 0016 §1 (400
   `invalid_return_to`, never rewritten). Creates the `login_attempts` row, sets
   `__Host-edisc_login` (httpOnly, Secure, SameSite=Lax, Path=/, Max-Age 600), redirects 303 to the
   IdP's authorization endpoint (code + PKCE S256, `state`, `nonce`; `prompt=login&max_age=0` for a
   re-auth). The IdP's endpoints come from its discovery document, cached, fetched only from the
   issuer registered in `tenant_idps` (https, no redirects to another host).
2. `GET /v1/auth/callback`: the login cookie's handle, the `state` and the row must all match, the
   row unexpired and unconsumed; it is consumed in the same statement that reads it
   (`UPDATE ... WHERE consumed_at IS NULL AND expires_at > now() RETURNING`). Code exchanged
   server-side; ID token checked (signature from the issuer's JWKS, `iss`, `aud`, `exp`, `iat` skew,
   `nonce`, `azp` when several audiences); the principal resolved by the ADR 0013 rules (active,
   `(issuer, subject)`). Re-auth: `auth_time` newer than the attempt's start AND the same principal as
   the existing session, else 403 `reauth_mismatch` and the old session untouched.
3. Session created: a NEW id (fixation: an id the browser held before is never promoted; on re-auth
   the old session is revoked `rotated` in the same transaction). Audit `session_created` (principal,
   IdP, `authenticated_at`, re-auth or not, user agent, request id; never the id or its hash).
4. **Cookie delivery after a cross-site redirect (amends ADR 0016).** The callback is reached by a
   navigation the IdP started, so the browser treats the whole redirect chain as cross-site: the
   `SameSite=Strict` session cookie is stored but NOT sent on a 303's next hop, and the UI would
   load signed out. The callback therefore answers 200 with a tiny static page (CSP
   `default-src 'none'`, no script) whose `<meta http-equiv="refresh" content="0;url=<return_to>">`
   starts a new, same-site navigation. Tested in Chromium, Firefox and WebKit (Playwright), because
   the rule is browser behaviour, not ours.
5. Failures redirect (through the same bounce page) to `/?auth_error=<code>` from the fixed list;
   provider error text is audited as a code only (never reflected, never stored verbatim).

### 1.3 Every request
- The caller dependency accepts a bearer token OR the session cookie; both present: 400
  `ambiguous_credentials` before either is evaluated (ADR 0016 §2).
- Cookie path: hash the id, read the row inside `tenant_tx` (RLS: a session of another tenant is
  invisible, so a cookie replayed against another subdomain is a plain 401), check not revoked, not
  past either expiry, principal still active; `last_seen_at` / `idle_expires_at` written at most
  once a minute (an UPDATE with a `last_seen_at < now() - 60 s` guard, no read-modify-write race).
- **Defence in depth for GET side effects.** Content routes are GETs with side effects (audit,
  forced anchor). SameSite=Strict already keeps the cookie off cross-site requests; in addition a
  cookie-authenticated request with `Sec-Fetch-Site: cross-site` is refused 403 (except the two
  callbacks, which do not use the session cookie). Bearer requests are unaffected.
- CSRF (ADR 0016 §3): state-changing methods with the cookie need `X-CSRF-Token` = HMAC(key, session
  id) compared in constant time, and `Origin` (else `Referer`) equal to the tenant origin; 403
  `csrf` otherwise. `GET /v1/auth/csrf` answers `{csrf_token}` with `Cache-Control: no-store`.
- Every cookie-authenticated response: `Cache-Control: no-store`, `Vary: Cookie`; HTML responses
  `frame-ancestors 'none'`. No CORS headers at all (same origin only).
- Throttling: login, callback and the token-submission route count failures in the existing
  per-(host, address) Redis throttle; a login burst cannot create unbounded `login_attempts` rows
  (per-address cap on open attempts, 429 above it).

### 1.4 Lifetime and revocation
- Absolute 12 h, idle 30 min, re-auth window 10 min (`EDISC_API_SESSION_*`, ADR 0016; decision D7
  confirms the numbers).
- **An open SSE stream does not count as activity** (it would keep an abandoned tab signed in for
  12 h): `last_seen_at` moves only on requests the user makes. Idle expiry closes the stream (§4).
- Revocation endpoints as ADR 0016: logout, `GET /v1/me/sessions`, self-revoke, admin revoke of a
  principal's sessions, and principal deactivation revoking all of them in the deactivation's
  transaction. All audited; revocation endpoints need a recent sign-in (except logout and
  self-revoking the CURRENT session, which must always work).
- IdP-side disablement is invisible to us until the session expires (we keep no IdP refresh token).
  The bound is the absolute lifetime. Back-channel logout (OIDC) and SCIM are BACKLOG (decision D8).

### 1.5 In-flight downloads and streams when a session is revoked
Content routes stream for minutes (a job or render package can be many GB). Today the audit is
committed and anchored before the first byte; nothing is re-checked afterwards.
- Proposed (decision D3): every streaming response authenticated by a session re-checks the session
  row at most every 15 s of streaming (at chunk boundaries, never inside a write) through one shared
  per-process `SessionWatch` (one query per session per 15 s, whatever the number of its streams).
  On revocation, expiry or deactivation the stream is ABORTED: the connection is reset without a
  terminating chunk (HTTP/1.1) or with `RST_STREAM` (HTTP/2), so the client sees an error, never a
  file that looks complete; for zips the central directory is never written, so a partial package
  is not a valid zip. An audit event `download_aborted` records the route, the object, the bytes
  sent and the reason (`session_revoked`, `session_expired`, `principal_deactivated`) and is
  anchored.
- What cannot be undone is said plainly in the docs: bytes already sent are out. The audit says how
  many.
- Bearer-authenticated streams are checked at the start only (we cannot revoke an IdP's token); the
  principal's active flag is re-checked on the same 15 s cadence.
- Alternative (cheaper, weaker): check only at the start. Not recommended: "revocation is immediate"
  is ADR 0016's promise.

## 2. Source install flows (ADR 0016 §5)

### 2.1 One table for both providers (migration 0037; FORCE RLS)
`oauth_installs`: `id`, `tenant_id`, `provider` (`slack`, `microsoft`), `client_id`,
`connection_id` (a `pending` connection for a new install, or the existing one for a re-auth),
`session_id`, `principal_id`, `state_hash`, `handle_hash` (the Lax install cookie, §2.2),
`pkce_verifier` (encrypted, as for logins), `nonce` (Microsoft), `requested_scopes`, `started_at`,
`expires_at` (10 min), `consumed_at`, `outcome` (`completed`, `denied`, `expired`, `replayed`,
`mismatch`, `failed`), `outcome_detail` (a code from a fixed list). Insert-only plus the consume
update, enforced by trigger.

### 2.2 Binding, state, PKCE, replay
- **State** is 256 bits, stored hashed, single use (consumed atomically, as for logins), 10 min,
  bound to tenant, client, connection, the acting session and the principal.
- **The browser binding cannot use the session cookie** (amends ADR 0016 §5): the provider's
  redirect back is a cross-site navigation, so the Strict session cookie is not sent. The start
  route sets `__Host-edisc_install` (Lax, httpOnly, Secure, 10 min) holding a random handle; the
  callback needs handle + state + row to match, and then re-reads the bound SESSION ROW (not the
  cookie): still live, same principal, and the principal still holds `connection.manage` on the
  client (permissions may have changed in 10 min). Any failure: `outcome` recorded, audited, nothing
  stored, the connection unchanged.
- **One callback host for every tenant (decision D1).** Slack and Microsoft need every redirect URI
  registered exactly; one per tenant subdomain does not scale (and Microsoft limits their number).
  Proposed: providers redirect to `https://oauth.<base>/v1/oauth/<provider>/callback`. That relay
  does NOT exchange anything and sets no cookie: it looks the state hash up through a SECURITY
  DEFINER function (returns only the tenant subdomain of an unexpired, unconsumed install; anything
  else: one generic error page), then 303s to the same path on the tenant host, carrying the query
  unchanged. The tenant host does everything else (cookie binding, exchange with the registered
  relay `redirect_uri`, storage). The code crosses one extra hop on our own domain; it is single use,
  minutes-lived and, where the provider supports it, PKCE-bound. `Referrer-Policy: no-referrer` on
  both hops.
- **PKCE:** S256 wherever the provider accepts it for confidential clients (Slack: confirm at build
  against Slack's current OAuth documentation and our app's settings; if not accepted, the
  client secret plus the bound state are the protection). Microsoft: see 2.4 (the consent leg has no
  code; the sign-in leg uses PKCE).
- **Replay:** a consumed or unknown state, a state presented with another install handle, or an
  expired one: `oauth_install_replayed` / `_expired` audited with the request id and the caller's
  address, never the state or code values.

### 2.3 Slack (our distributed app, OAuth v2)
- Start: `POST /v1/clients/{c}/connections/slack/install` (`connection.manage`, CSRF) with optional
  `{"connection_id"}` for a re-authorization. Scopes per tier from one table in
  `edisc_connector_slack` (the same table `validate_connection` uses for blind spots). Answers
  `{authorize_url, connection_id}`; the UI follows only `https:` URLs on `slack.com`.
- Callback: exchange with `oauth.v2.access` (through `call_with_limits`, bucket
  `(tenant, slack, -, oauth.v2.access)`); the response's tokens are registered with the redactor the
  moment the body is parsed, before any branch, then encrypted (§2.5).
- **Workspace binding.** The team id (and enterprise id for Grid) come from Slack's exchange
  response, never from the browser. A re-authorization must return the SAME team/enterprise as the
  connection recorded; otherwise `mismatch`, nothing stored, audited, the connection unchanged. A
  client admin can therefore never re-point a connection with collected evidence at another
  workspace.
- Granted scopes are what Slack returns, not what we asked; blind spots are recomputed from them
  (`validate_connection`), recorded on the connection, and (§7.2 of ADR 0018) in every later
  `job_started`.
- Denial (`error=access_denied`): connection stays `pending` (or keeps its previous token on a
  re-auth), `install_error=denied`.

### 2.4 Microsoft Teams (multi-tenant app, admin consent, client credentials)
- **The admin-consent redirect is unsigned.** Its `tenant` and `admin_consent=True` query parameters
  can be typed by anyone holding a valid state, i.e. by the client admin who started the flow. And
  once ANY customer's Entra tenant has consented to our app, a client-credentials token for that
  tenant can be obtained by us at any time. So "verify consent by acquiring a token for the
  `tenant` in the callback" would let customer B start a consent flow, edit the callback to
  `tenant=<customer A's Entra tenant>`, and get a connection to A's Microsoft 365 data. **The
  callback's `tenant` parameter is never trusted.**
- Proposed (decision D2): consent is done through the authorization-code endpoint with OIDC
  (`/authorize` with `prompt=consent`, our app's `.default` scope, `openid`, PKCE, nonce), so the
  callback yields an ID TOKEN signed by Microsoft. Its `tid` (checked signature, issuer
  `https://login.microsoftonline.com/<tid>/v2.0`, audience, nonce) is the Entra tenant we bind, and
  the signed-in user must be an administrator of it (the `wids` claim holding the Global or
  Privileged Role Administrator template id; confirm the claim set at build). Then a
  client-credentials token for that `tid` (certificate, `private_key_jwt`) lists the granted app
  roles (`roles` claim) = the granted permissions, recorded; missing ones are recorded as a partial
  grant with blind spots.
- **One Entra tenant, one of our tenants** (decision D2b): a unique registry across tenants (a
  SECURITY DEFINER insert into an owner-only table keyed by `tid`) refuses binding an Entra tenant
  already bound to another of our tenants, with an alert to operations. A legitimate move is an
  operator action.
- Graph tokens are never stored long-term: client credentials are fetched on demand with the
  certificate (ADR 0009 preference); the certificate is a platform secret (KMS), registered for
  redaction, with an expiry alert 30 days ahead.

### 2.5 Where tokens are encrypted, and what is audited
- Encryption happens in the callback request itself, through `connection_tokens.store_tokens`
  (`SecretBox` over the tenant's KMS key, context tenant + connection + purpose). The plaintext lives
  only in that request's memory; it never enters a log line (redactor first), an error detail (the
  global 422 fix, §0), an audit or custody payload, a redirect URL, a response, or Temporal.
- **Journal first (crash safety):** the exchange response's tokens are written ENCRYPTED to a
  journal row in their own transaction before the connection is updated (the ADR 0009 pattern for
  refresh responses); `reconcile_installs` at worker start applies or expires journaled installs. A
  crash between the exchange and the update never leaves a live token we cannot find.
- Audit (tenant stream, `edisc_api.audit.record`, request id, actor = the session's principal):
  `oauth_install_started` (provider, client, connection, requested scopes, expiry),
  `oauth_install_completed` (team / enterprise id or Entra `tid`, granted scopes, blind spots, token
  type, token version, `authenticated_at` of the session), `oauth_install_denied` (provider error
  code from a fixed list), `oauth_install_expired`, `oauth_install_replayed`,
  `oauth_install_mismatch` (expected vs returned workspace/tenant ids), `oauth_install_failed`
  (exchange error class). Never a token, code, state, verifier or any part of them.

### 2.6 How a revoked or expired token surfaces: as paused jobs first, then access-lost units
- Detection is unchanged: a source call answering `invalid_auth`, `token_revoked`,
  `account_inactive`, `token_expired` (Slack) or a token request failing with a consent error
  (Microsoft) raises `AuthenticationError` with a reason class: `credentials_revoked`,
  `credentials_expired`, `consent_withdrawn`, or `platform_credential_expired` (OUR certificate:
  an operations alert, never the customer's fault).
- New: a daily `check-connections` maintenance schedule calls `auth.test` (Slack) / acquires a
  client-credentials token (Microsoft) through the rate limiter for every active connection, so a
  revoked token turns the connection `reauth_required` (alert, SSE `connection` event on open job
  streams) before the next job finds out.
- Paused jobs (today) wait without limit. Proposed (decision D5): a pause deadline
  (`EDISC_REAUTH_DEADLINE_HOURS`, default 168) and an explicit "finish without access" action
  (`POST /v1/jobs/{id}/finish-without-access`, `job.resume` + a reason + recent sign-in). Either
  way the job leaves the pause by closing every unit not yet reconciled as **`access_lost`** with the
  reason class above, each unit's fact recorded in the chain (`unit_reconciled`, §28 format), and
  finishes `completed_with_gaps`. The report states the reason per unit and the pause (who, when,
  how long). A re-authorization before that resumes the job as today. Nothing is ever left
  "unsettled" by a revoked token.
- Tests: revoke the dummy connector's token mid-job → pause → deadline (test-tuned) → every
  remaining unit `access_lost` `credentials_revoked` in the chain, `units.jsonl` recomputed byte for
  byte from the package; re-auth before the deadline resumes with zero gaps.

## 3. The UI's read endpoints

### 3.1 Permissions
- `GET /v1/me/permissions`: `{scopes: [{scope_type, scope_id, permissions}]}` for the tenant and
  every client/matter/workspace where the caller holds a role directly or through a group, computed
  by `authz.permissions(roles_at(...))` (the same code path `authorize` uses). Paginated
  (keyset on `(scope_type, scope_id)`), because a principal at a large firm may hold thousands of
  matter roles. Effective permissions include inherited ones only implicitly: the UI asks the API
  whenever it matters, the endpoint is a hint for showing controls.
- `GET /v1/roles`: generated from `ROLE_PERMISSIONS` (a test edits a role in a fixture and sees the
  endpoint follow; a static test fails if the route returns anything not derived from it).

### 3.2 Jobs list, custody events, groups
- `GET /v1/jobs`: tenant-wide, only jobs on matters the caller can read (`visible_ids("matter")`;
  for a caller with thousands of visible matters the filter is a join on the caller's role
  assignments, not a giant `ANY(:ids)`). Filters: status, clean basis, client, matter, connection,
  source, created/finished range. Order: newest first, keyset on `(created_at DESC, id DESC)` with an
  index `(tenant_id, created_at DESC, id DESC)`.
- `GET /v1/jobs/{id}/custody/events` (`custody.read`): keyset on `seq`, `limit` <= 500 and a byte
  budget per page (1 MiB of payload: a page ends early rather than exceeding it), payload included
  (it never held a secret; `job_started.export.findings` holds capped samples). A 1M-unit job has
  more than 2M events: pages are by seq, never by offset; no total count.
- `GET /v1/groups`, `GET /v1/groups/{id}/members` (`tenant.admin`), keyset on id.
- **Cursors** become `{position, filter_digest}`: a cursor used with different filters (or on
  another route) is 422 `cursor_mismatch` instead of silently skipping rows. They stay unsigned:
  they are positions, and every page re-applies tenant RLS and the caller's visibility, so a forged
  cursor can only move the window within what the caller may see.

### 3.3 Directory snapshots (`GET /v1/connections/{id}/directory?kind=conversations|users`)
- **Never calls the source on a request.** A `refresh-directory` activity (maintenance schedule,
  plus one run after a connection is created or re-authorized) pages the source through the limiter
  into a NEW snapshot generation: `directory_snapshots` (id, connection, kind, status
  `capturing`/`complete`/`failed`, started, completed, counts, source cursor checkpoint) and
  `directory_entries` (snapshot id, external id `COLLATE "C"`, display name (replacement text +
  exact code units for lone surrogates, §23), a normalized search key, kind, archived flag). The
  connection's `current_snapshot` moves only when a generation is complete; a partial one is never
  served as complete.
- Grid scale: Enterprise Grid can hold hundreds of thousands of users and tens of thousands of
  channels. At Slack's Tier 2 limits a full users listing takes hours; the activity checkpoints the
  source cursor in the snapshot row (resumable after a SIGKILL, CLAUDE.md principle 5), heartbeats,
  and streams entries in bounded batches (principle 8). Generations older than the current and the
  previous one are marked superseded (rows kept per the no-delete rule; archiving is BACKLOG).
- Serving: keyset on `(search_key, external_id)`; optional `q` (prefix on the normalized key, index
  `text_pattern_ops`); `limit` <= 500; the cursor binds the snapshot id, so paging continues in the
  generation it started in even if a newer one completes (the previous generation is kept for that);
  every page carries `snapshot_id`, `captured_at`, `refresh_running`, `approximate_total`. "Not
  captured yet" is a distinct state, never an empty list.
- Exports: the snapshot is built from `export_conversations` + `users.json` once, no source call.
- Who sees it: `connection.read` on the client, or `job.start` on a matter of that client (the
  scope picker). The names of every workspace user are personal data: decision D12.

### 3.4 What each role sees (ADR 0013 roles; 404 when invisible, 403 when visible but not permitted)
| Endpoint | tenant_admin | client_admin | matter_manager | collector | reviewer | auditor |
|---|---|---|---|---|---|---|
| `/me/permissions`, `/roles`, `/me/sessions` | own | own | own | own | own | own |
| `GET /jobs` | all | jobs on matters of their clients | their matters | their matters | their matters | their matters |
| custody events | all | their clients | their matters | 403 | 403 | their matters |
| directory | all | their clients | 403 (no `connection.read`) unless `job.start` | via `job.start` | 403 | 403 |
| groups | yes | 403 | 403 | 403 | 403 | 403 |
| job stream (SSE) | all | their clients | their matters | their matters | their matters | their matters |
| install start / token submit | yes | their clients | 403 | 403 | 403 | 403 |
Each row is a parametrized test (role x endpoint x own/other scope x other tenant).

### 3.5 Tenant isolation tests (every new table and route)
- Two tenants with colliding external ids (same Slack team id, same conversation ids, same user
  ids): every list and get from tenant B's host returns only B's rows; A's ids on B's host → 404.
- A's session cookie value sent to B's host → 401 (RLS hides the row; the cookie is host-only
  anyway, this proves the server side too). A's install state on B's host → `replayed`. A's cursor on
  B's host → only B's window.
- The FORCE RLS + no-DELETE + coverage test (existing) includes `sessions`, `login_attempts`,
  `oauth_installs`, `directory_snapshots`, `directory_entries`; the cross-tenant registry of Entra
  tenants is owner-only with a definer function, tested like the existing definer functions.

## 4. Live updates: Server-Sent Events (`GET /v1/jobs/{id}/stream`)

- **Auth:** cookie (an `EventSource` sends same-origin cookies; it is a GET, so no CSRF token; the
  `Sec-Fetch-Site` rule applies) or bearer (`fetch` streaming). `job.read` on the job's matter at
  open; the same 404/403 rules.
- **Events** (`text/event-stream`, UTF-8, `id: <custody seq of the job head>`): `job` (status
  verbatim, clean, clean basis, caveat, unit counts by status and recon status, pause state),
  `units` (keys + status + recon status + counts of units changed since the last event, at most 500
  per event; more → a `resync` hint), `connection` (the job's connection turned
  `reauth_required`), `revoked` (final, with a reason code), `sealed` (final). Each event is a pydantic
  model in `edisc_api.stream_events`; the stream writes only those models.
- **Never evidence content:** the stream module reads only `collection_jobs`, `work_units`,
  `job_pauses`, `connections` (status column) and the custody head; it imports nothing from
  `edisc_evidence`, S3, the normalizer or derivations (a static import test, like the renderer purity
  test) and its SQL is an allow-listed set of statements (a test parses them). A canary test puts a
  unique string in message texts, file names, channel names and user names of a dummy dataset,
  streams a whole job, and asserts the canary never appears in the stream's bytes. Unit keys and
  conversation ids appear, as they already do in `GET /jobs/{id}/units` under the same permission;
  names never do.
- **Reconnection:** the client resends `Last-Event-ID`; the server validates it as an integer (else
  ignores it) and answers with a fresh `job` snapshot, then changes. Events are states, not deltas,
  so a missed event is repaired by the next snapshot; nothing is replayed from a buffer. `retry:
  3000` is sent once.
- **One source per job, fanned out:** one poll per job per API process, once a second while it has
  subscribers, comparing the custody head seq and `collection_jobs.updated_at` before querying
  anything else (decision D4: polling, not LISTEN/NOTIFY, which needs a dedicated connection per
  process and breaks under transaction pooling). 100 tabs on one job = one cheap query a second per
  process.
- **Backpressure:** each subscriber has a bounded queue (64 events). The producer never blocks on a
  slow client: on overflow the queue is cleared and a single `resync` marker is queued, which the
  writer turns into a fresh snapshot. A client whose socket write has not progressed for 30 s is
  disconnected (it will reconnect and get a snapshot). Memory per subscriber is bounded by the
  queue, not by the job.
- **Re-checked continuously:** every 15 s (the heartbeat comment) the session row (not revoked, not
  expired, idle included) and `job.read` are re-checked through `SessionWatch` (§1.5); on failure a
  final `revoked` event and close. Maximum stream lifetime 30 min, then `retry` makes the client
  reconnect (and re-authenticate). Per-principal cap 10 concurrent streams (429 above).
- **No buffering by proxies:** `Cache-Control: no-cache, no-transform`, `X-Accel-Buffering: no`,
  no compression middleware on the route; a test asserts the first event arrives before the
  handler's second poll through a real uvicorn (not `ASGITransport`, which buffers differently).
- **Fallback:** the UI polls `GET /v1/jobs/{id}` and `/units` every 5 s if the stream fails; the
  wire formats are the same models.

## 5. OpenAPI and `oasdiff` in CI

- `make openapi` writes `docs/api/openapi.json` (sorted keys, stable `operationId` per route =
  function name, no server URL, generated from the app without settings that vary per environment);
  CI regenerates and fails on any difference (the drift check).
- `oasdiff breaking` (pinned release by checksum; run in CI as a binary or digest-pinned image)
  compares the generated spec with the one on the merge base; any ERR-level finding fails the job.
- **Breaking** (CI fails):
  - a removed path, operation, response status, response field, or enum value in a response;
  - a new required request field or parameter, a required field made required where it was
    optional, a request enum value removed;
  - a type change or narrowing (string → integer, nullable → non-nullable in a request, `maxLength`
    lowered, `pattern` added, `minimum` raised), a changed default;
  - a response field that becomes optional or nullable (a typed client breaks);
  - a changed `operationId` (generated client names) or media type;
  - **ours, checked by a small script because oasdiff does not know them:** a change of
    `x-permission` on an existing route, a removed error code from a route's documented error list,
    and any change to the SSE event schemas (kept as components with an `x-sse-events` list).
- **Not breaking** (allowed, shown in review): new paths, new optional request fields, new response
  fields, a new enum value in a RESPONSE (decision D9: allowed, because the UI treats unknown
  enum values as "unknown" by rule; oasdiff's warning is surfaced in the job summary).
- An intended break needs `/v2` or a reviewed entry in `docs/api/breaking-allowlist.yaml` naming the
  oasdiff rule id, the operation, the reason and the frontend commit that absorbs it; an entry
  without all four fails CI.
- The frontend generates its types from this file on its own branch; `pending.ts` entries map onto
  generated schemas as routes land. Note: the frontend's assumed `DirectoryOut` (one unpaginated list
  of conversations and custodians) is not what §3.3 ships: the change is flagged to that branch.

## 6. The one exception: Slack internal-app token submission (ADR 0016 §6)
- `POST /v1/clients/{c}/connections/slack/token` and `PUT /v1/connections/{id}/token`
  (`connection.manage`, CSRF, recent sign-in). Body `{"token": "<xoxb-...>"}`, JSON only, a 4 KiB
  body limit enforced before parsing.
- Order of operations: read the raw body → register the candidate value with the redactor → parse
  (the global 422 handler never echoes, §0) → shape check (prefix `xoxb-`, length bounds, charset)
  → `auth.test` through the limiter (the team id, enterprise id, bot id and token type come from
  Slack's answer, never from the browser) → re-auth must match the recorded team (as §2.3) →
  `store_tokens` → audit `connection_token_submitted` / `_replaced` (actor, time, team id, token
  type, scopes from `auth.test` headers, `authenticated_at`) → 201/200 with the connection (status,
  `token_set_at`, token type; nothing else about the token).
- Write-only: no route returns it or any part of it (no last-4, no hash).
- Rejected tokens: `invalid_auth` from Slack → 422 `token_rejected`, audited without value,
  throttled like auth failures (a guessing oracle otherwise).
- Tests: a canary token through every path (valid, rejected, malformed, misplaced field, wrong type,
  over-long, duplicate submission, concurrent replace) never appears in any response, header, log
  line (the redaction capture), audit or custody payload, Temporal history (the test reads the
  histories), or the database outside the encrypted column (a scan of every text/jsonb column of the
  tenant's rows).

## 7. Threat model: the attacks expected, and the test for each

## 8. Crash points (each with a test that kills there and checks the outcome)
| Point | Outcome required |
|---|---|
| Login callback after the state is consumed, before the session row commits | No session; the user signs in again; the attempt shows `consumed` without a session (audited as failed) |
| After the session commits, before the response | A session exists that no browser holds; it idles out in 30 min; harmless and audited |
| Re-auth after the new session commits, before the old one is revoked | Impossible by construction: one transaction. Tested by killing inside it (both or neither) |
| Install callback after the provider exchange, before the encrypted journal row | The token is lost to us; the provider-side install remains: `reconcile_installs` cannot see it, so the install outcome stays `failed` and the user is told to retry; for Slack a re-install reissues the bot token (confirm at build); the orphaned-token risk is recorded |
| After the journal row, before the connection update | `reconcile_installs` (worker start and a schedule) applies it exactly once (token version compare-and-swap) |
| After the connection update, before the audit | Same transaction: both or neither |
| Admin revocation / principal deactivation mid-way | One transaction: every session of the principal revoked, or none |
| Directory refresh SIGKILLed mid-pagination | Resumes from the snapshot's checkpoint; `current_snapshot` never points at a partial generation; zero duplicate entries (unique per snapshot) |
| API process killed with open SSE streams | Clients reconnect with `Last-Event-ID` and get a fresh snapshot |
| API process killed mid-download | The download was audited and anchored before the first byte; no `download_aborted` is written; the client sees a broken transfer, never a complete-looking file |
| Token submission after `auth.test`, before `store_tokens` | Nothing stored; resubmitting works |
| Pause deadline job (§2.6) killed between closing units | Each unit closes in its own transaction with its chain event; a rerun closes the rest; the final event only after all |

## 9. Mutation plan (round `m17`, one catalog entry each; the test named must fail)
- Sessions: fixation (reuse the old id), expiry checks removed (idle, absolute), revocation not
  checked, principal-active not checked, `last_seen` throttle inverted, cookie flags (`HttpOnly`,
  `Secure`, `SameSite`, `__Host-` prefix, `Domain` added), cookie + bearer accepted.
- CSRF: token not compared, compared non-constant-time is not observable (no entry), Origin check
  removed, `Sec-Fetch-Site` check removed, bearer wrongly required to send a token.
- Login: state not single-use, nonce not checked, `return_to` validation removed (each rule one
  entry), re-auth `auth_time` and same-principal checks removed, bounce page replaced by a 303.
- Installs: state replay allowed, install handle not checked, `connection.manage` not re-checked,
  Slack team mismatch accepted, Microsoft callback `tenant` trusted instead of the ID token `tid`,
  Entra uniqueness not enforced, journal skipped, token value in the audit payload, 422 `input`
  echo restored.
- Token submission: redactor registration moved after parsing, value in the error detail, team id
  from the body, throttle removed.
- Lists: visibility filter removed from `GET /jobs`, cursor filter digest not checked, custody
  events byte budget removed, directory served from a partial generation, directory GET calling the
  source.
- SSE: `job.read` not re-checked, session not re-checked, queue unbounded, a name field added to
  the `units` event (the canary must catch it), evidence import added to the stream module, proxy
  headers removed.
- Access loss: pause deadline ignored, units left unsettled instead of `access_lost`, reason not in
  the chain.
- OpenAPI: drift check skipped, an `x-permission` change not detected, allow-list entry without a
  reason accepted.

## 11. Changes to ADR 0016 this plan needs (the amendment)
1. Cookie delivery after cross-site redirects: callbacks answer with a same-site bounce page, not a
   303 (§1.2.4).
2. Install flows bind the browser with a Lax `__Host-edisc_install` handle and re-read the session
   ROW; the Strict session cookie never reaches the callback (§2.2).
3. One OAuth relay host for every tenant (§2.2, D1).
4. Teams consent through `/authorize` with OIDC: the signed ID token's `tid` is bound, never the
   callback's `tenant`; one Entra tenant per our tenant (§2.4, D2).
5. In-flight downloads and streams are cut within 15 s of revocation (§1.5, D3).
6. Revoked or expired credentials end as `access_lost` units after a deadline or an explicit action
   (§2.6, D5); amends ADR 0012's open-ended pause.
