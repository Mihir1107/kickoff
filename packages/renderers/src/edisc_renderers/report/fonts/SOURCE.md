# Report fonts (ADR 0018 §5.4, §5.5)

The fonts themselves are NOT in the repository: the report image fetches them at build from pinned
commit URLs and verifies each SHA-256 (`deploy/report-image/fonts.lock`, `fetch_fonts.py`); the
variable fonts (Noto Sans SC, Noto Sans KR, Noto Emoji, from `google/fonts`) are instanced to a static
Regular (wght 400) at build with timestamps not recalculated. The TrueType CJK fonts replace the
CID-keyed CFF `noto-cjk` files, which failed PDF/A after HarfBuzz subsetting (spike S1). No Japanese
font: Japanese renders with the SC glyph forms (Han unification, §5.4).

- `LICENSES/`: the SIL Open Font License 1.1 texts, fetched with SHA-256 pinned in `fonts.lock`
  (`OFL-notosans.txt` covers Noto Sans, Noto Sans Mono, Hebrew, Devanagari and Thai, which carry the
  same "Noto Project Authors" OFL; Arabic, SC, KR and Emoji have their own copies).
- `coverage.txt`: the union of the vendored fonts' cmaps (code point ranges), generated by
  `scripts/report_font_coverage.py` from the fonts of `fonts.lock` and committed, so the report HTML
  builder can replace every character no vendored font draws by its marker (§5.5) without the fonts.
  A unit test ties its header to `fonts.lock`; a test inside the report image recomputes it from the
  installed fonts. Changing a font changes the coverage, which is a report renderer bump.
